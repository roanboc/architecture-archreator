# Domains

_[← EA home](../README.md)_

**Not used.** This tree is
[Depth 1 — Application](../README.md#modeling-depth): the subject is one
deliverable, not an organization, so there is nothing to split. Everything
lives in the numbered layer folders above.

The folder stays rather than being deleted, because an empty folder that says
why is a known gap and a missing one is an unknown gap.

**When this would be used.** A domain is a part of an organization modeled as
though it were an organization in its own right — its own customers, services,
capabilities and approver. That is a Depth 3 question, and it is asked one tree
up if it is ever asked at all. The `model-domains` skill holds the test and the
charter format; they are not restated here, because a copy of a rule is a rule
that drifts.
